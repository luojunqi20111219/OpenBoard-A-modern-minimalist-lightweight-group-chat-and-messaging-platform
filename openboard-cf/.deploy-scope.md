# 部署操作边界（重要）

> 记录于 2026-09-30。任何自动化操作前先读本文件。
>
> 本文件是**部署纪律**的记录，不是配置来源。真实的资源 ID 在 `wrangler.toml` 里。

## 原则

**只操作带 `openboard-` / `openboard` 前缀的资源。**

同一个 Cloudflare 账户下通常部署着多个互不相关的项目
（聊天、网盘、邮件……）。自动化脚本一旦按「名字看起来像」去猜资源，
极易误删误改**其他项目的生产数据**。因此本项目所有资源统一加前缀，
且每次操作前必须逐个核对名字。

## 本项目允许操作的资源（全部带 openboard 前缀）

| 类型 | 名称 | 说明 |
| :--- | :--- | :--- |
| KV | `openboard-kv` | 登录限流计数 + 在线状态快照 |
| KV | `openboard-sessions` | 预留（当前未使用，可删除） |
| R2 | `openboard-uploads` | 聊天文件与头像 |
| D1 | `openboard-db` | 全部业务数据 |
| Worker | `openboard` | 主部署单元（assets + API + DO 三合一） |
| Route | `<你的域名>/*` | 指向 `openboard` |
| Pages | （无） | 已废弃，见下方变更记录 |

## 2026-09-30 架构变更记录

| 动作 | 对象 | 原因 |
| :--- | :--- | :--- |
| **删除** | Pages 项目 `openboard-a-modern-...` | Pages 无法穿透服务绑定返回带 WebSocket 的 101 响应（error 1101）。删除前已解绑其自定义域。 |
| **删除** | Worker `openboard-chat-hub` | DO 已内联进主 Worker，不再需要独立部署单元。 |
| **新增** | Worker `openboard` | 单 Worker 承载 assets + API + DO。 |

## 操作纪律

1. 只对「允许操作的资源」表里列出的资源发起写操作。
2. 不执行任何 DELETE / 覆盖已存在资源的 PUT，除非明确点名该资源。
3. 每次批量操作后**回读资源列表**，确认其他项目的资源未发生变化。
4. 删除 Pages 项目前必须先解绑全部自定义域，否则 Cloudflare 会拒绝：
   `To delete your project, you must first delete all custom domains associated with your project.`
5. 迁移验证期间产生的测试数据（临时账号、测试消息）必须清理干净，
   只保留种子数据（`filehelper`）。

## 凭据与权限的注意点

- **API Token 权限不足时的表现**：读接口报 `code: 10000 Authentication error`，
  写接口报 `code: 10405 Method not allowed for this authentication scheme`。
  这两者**都不代表 token 无效**，而是该 token 缺少对应 scope。
- **`/user/tokens/verify` 对账户级 `cfat_` token 会误报「Invalid API Token」**，
  这是已知行为，**不要因此重新创建 token**。
  正确做法是用 `/accounts/{account_id}/tokens/verify` 验证。
- **绑定自定义域需要 `Zone:Workers Routes:Edit`**，
  但**不需要** `Zone.DNS:Edit`（前提：域名已有 proxied DNS 记录）。
- **沙箱/CI 环境下 `api.cloudflare.com` 可能被 DNS 劫持**，
  可用 `curl --resolve api.cloudflare.com:443:<真实边缘IP>` 绕过。
