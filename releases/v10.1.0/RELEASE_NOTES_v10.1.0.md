# OpenBoard v10.1.0 发布说明

> **主题：密码自己能救回来** — 把"请联系管理员"从一句空话，变成用户自己点得动的一个按钮

发布日期：2026-10-02

---

## 一、这个版本解决了什么问题

v10.0.0 把 scrypt 账号登录失败时的提示改成了「请联系管理员重置密码」，
并且专门做了一个**管理员安卓客户端**，本意是给用户一条出路。

但上线后暴露了一个更根本的问题 —— 用户的原话是：

> "你倒是给一个联系他的方式啊，我都没有联系方式，我怎么联系呀？我怎么发呀？"

这句话点破了 v10.0.0 那个提示的本质：**它是一个假修复**。

- `admin_contact.admins` 列出来的只是 OpenBoard 站内的**账号名**
- 而用户已经**登不进 OpenBoard** 了
- 站内信发不出去，聊天记录看不到，管理员是谁都不知道
- 结果就是：界面告诉他"去联系管理员"，他却**没有任何可用的渠道**

一句话：**让一个进不来的人，去找一个他够不着的人。**

v10.1.0 把这条路真正打通了。

---

## 二、核心改动：自助重置为默认密码

登录时如果服务端返回 400（说明这个账号的密码在 Workers 上算不动），
客户端现在会显示一个**「重置为默认密码」按钮**：

```
点按钮
  ↓  二次确认弹窗（说明后果）
重置为默认密码 12345678
  ↓  自动用 12345678 登录
强制全屏改密页（不给返回键）
  ↓  设置自己的新密码
正常进入聊天
```

### 为什么这件事是安全的

这个功能最容易被误解成"任何人只要知道用户名就能改别人密码"。
**不是。** 它能动的只有一个极窄的口子，由三条边界守着：

| 边界 | 规则 | 挡住的攻击 |
|---|---|---|
| **边界 1** | 只能重置「密码本来就算不动」的账号 | 否则知道用户名就能把别人密码设成 12345678，登进去读完所有聊天记录 |
| **边界 2** | 管理员账号（role=1 / ALLOWED_ADMINS / D1 is_admin 三层）与系统账号一律拒绝 | 否则是一条完整提权链：枚举管理员名 → 重置 → 登管理端 |
| **边界 3** | 每账号每天 1 次、每 IP 每天 10 次 | 否则可以反复重置骚扰 |

关键在**边界 1**：这类账号本来就**没有任何人能登录**（scrypt 在 Free 计划
上物理算不完），所以重置它**不构成窃取**，只是把一扇已经打不开的门换把锁。

> 补充：重置后的密码虽然公开是 `12345678`，但登录后会**强制全屏改密**。
> 改密页拦截返回键，不改成自己的密码就出不去。

## 三、客户端自动识别服务端类型

用户的另一个要求：

> "可以自动检测哪个服务器端是 cloudflare 还是普通的？如果是普通的话，就不会触发这个"

新增 `GET /api/capabilities`（无需登录），返回：

```json
{
  "server": "cloudflare-workers",
  "version": "v10.1.0",
  "features": {
    "self_reset_password": true,
    "must_change_password": true,
    "admin_grants": true,
    "legacy_hash_unsupported": true
  }
}
```

客户端的判定逻辑是**严格默认**：

- 探测成功且 `self_reset_password === true` → 显示按钮
- **探测失败 / 超时 / 老版本服务端没有这个接口 → 不显示按钮**

绝不做"没说不支持就是支持"的宽松兜底 —— 在普通（Python/FastAPI）服务端上，
它根本不会触发，界面和以前完全一样。

## 四、服务端迁移说明（部署必看）

本版给 `users` 表加了 `must_change_password` 列，**必须先执行迁移**：

```bash
npx wrangler d1 execute openboard-db --remote \
  --command "ALTER TABLE users ADD COLUMN must_change_password INTEGER NOT NULL DEFAULT 0"
```

或者在管理端 App 里点「应用迁移」。

### 如果忘了迁移会怎样

**不会崩，会降级。** 重置密码照样成功、照样能用 12345678 登录，
只是"强制改密"这个约束不生效（响应里会带 `migration_required: true` 如实告知）。

这条降级路径是**故意设计的** —— "灌完 schema、还没点应用迁移"是部署流程里
一个完全正常的中间状态，不能让它变成 500。

> ⚠️ 这里刻意没把 `is_admin` / `must_change_password` 写进 `schema.sql` 的
> `CREATE TABLE`。它们就该由迁移负责，写进去会让 `migration_status` 在任何
> 环境下都报 `ready=true`，迁移到底跑没跑过就再也测不出来了。

## 五、本次同时修掉的两个真实缺陷

### 1. 部署检查的假阴性（很危险）

`makeUser` 测试助手在 `is_admin` 列不存在时**静默跳过**了这个参数，
造出来的其实是普通用户。于是「D1 动态管理员不能自助重置」这条关键安全断言，
**因为错误的理由通过了** —— 给人虚假的安全感。

修复：需要管理员时主动 `ALTER TABLE` 补列，确保断言真实有效。

### 2. 检查顺序错误

项目内自测发现：把限流检查放在 `needsPasswordReset` 之前才对。

顺序反了的话，第一次重置后密码变成 pbkdf2，"需要重置"不再成立，
第二次请求会拿到 `400 该账号可以正常登录`，而不是本该返回的
`429 今天已经重置过密码了` —— 用户会以为自己点错了，而去反复尝试。

### `test:reset` —— 专门为这个功能写的边界穷举

**以负向断言为主**，重点证明"不该能重置的确实重置不了"：

- 正常密码账号被拒（边界 1）+ 密码确实没被改
- role=1 / 硬编码名单 / D1 is_admin **三条路径**的管理员全部被拒（边界 2）
- 系统账号、封禁账号被拒
- 同日二次重置 429；**换 IP 头绕不过账号级限流**
- 大小写变体不会凭空放行（`getUserByName` 是大小写敏感精确匹配）
- 每次成功重置都写审计日志，`actor` 标为 `self-service`
- 未迁移环境下：重置仍成功、改密仍可用、**边界一条都没放松**

### `test:live` —— 部署契约验证

用它是因为 **沙箱无法直连线上接口**：`*.workers.dev` 与 Cloudflare 边缘 IP
的 TLS 在这里是被阻断的（`SSL_ERROR_SYSCALL`），curl 打不通。

而"部署成功"本身 wrangler 已经确认了（Version ID + 100% 流量 + D1 已迁移）。
真正还需要证明的是：**构建出来推上去的那份代码，行为是否正确**。

所以 `test:live` 用 `dist/worker.js` —— **与 `wrangler deploy` 上传的完全同一份
产物** —— 在隔离 Miniflare 里跑完整链路，绑定值对齐 `wrangler.toml`。
它测的不是"另一份代码"，而是**线上正在跑的那份**。
